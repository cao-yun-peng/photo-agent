## 改变了什么

原来搜索计划创建后只有45秒可用于后续核验，用户查看照片的时间也包含在内。现在新计划把时间、累计资源和状态有效期分开：用户第一次搜索花5秒，看照片60秒，再点击继续找，仍能在计划有效期内续查，调用额度保持累计。

| 控制 | 实现与默认值 |
| --- | --- |
| 单次执行时间 | `SearchExecution` 使用 `monotonic()`；普通搜索45秒，嵌套解析、召回、核验和兜底继承同一截止时间 |
| Agent 工具时间 | 2026-09-10修正：首次/续查/兜底/浏览默认执行30秒，外层35秒含5秒清理；显式工具超时优先，内部执行不超过45秒。请求全部结果保留外层至少60秒、内部最多45秒。通用工具15秒不再截断搜索 |
| 后台预取时间 | 独立执行段默认25秒，外层30秒，保留状态保存和取消清理余量 |
| 整个任务累计额度 | Redis Lua 原子预占：20次模型调用、3次视觉调用、60次候选核验尝试、60个成本单位；分页、预取、派生计划共享 `budget_id` |
| 搜索计划有效期 | 默认600秒；预算、快照与游标使用同一固定 `expires_at`，翻页与派生计划均不延期 |

这些是当前默认配置，不是新测得的响应延迟。成本单位为内部权重，并非人民币金额；Token仍是供应商返回后的统计，本轮没有新增Token或人民币硬限额。

## 核心源码

`app/services/search_budget.py` 的 `search_execution()` 在最外层建立计时上下文，内部调用复用同一对象。只有新的后台任务使用 `fresh=True`。`SearchBudget` 继续管理共享资源额度，新Redis记录使用 `schema_version=2` 和固定到期时间。

```python
with search_execution(timeout_seconds) as execution:
    with budget.activate():
        # 子调用继承 execution；实际模型调用前仍须原子预占共享额度。
        result = await service.search(request, plan_id=existing_plan_id)
```

`app/services/search_engine.py` 将查询解析、搜索和兜底入口接入同一执行段。`_collect_page()` 只在整个核验批次完成后追加 `accepted` 并推进 `scan`，响应构建位于执行计时器外，能够返回超时前已经得到的结果。

| 停止原因 | 持久状态与响应 |
| --- | --- |
| `request_timeout` | 保存进度，不写永久 `terminal`；返回已得到的照片和可续游标，内部 `search_pending=True` |
| `budget_exhausted` | 写入终止原因，禁止新增核验；已接受结果仍可分页读取 |
| 旧预算 `deadline_exceeded` | 保留旧规则，不通过升级刷新额度或复活旧计划 |
| 真正扫描完候选 | 结合索引覆盖、候选上限、核验不确定项等条件判断是否耗尽，不能用“本次没有照片”替代完整性证明 |

初始化中的Embedding/召回超时也可返回已有计划的游标。原图核验超时会暂停未完成批次，不把不确定照片改成匹配，也不把该批次标为已扫描。

## 缓存、取消与并发

- `search_cache.py` 的缓存等待与实际计算受本次执行时间约束；等待者超时不会延长或取消另一请求的计算。只有真实缓存未命中、即将发出的模型调用才预占额度。
- 已发出或结果不明的模型调用不退款。取消后重试一个未完成批次会再次计入候选核验尝试；有效的已完成模型缓存可以避免重复调用，但不承诺所有取消都零重复费用。
- 一个预算可能被多个派生计划并发使用，因此额度继续通过Lua原子检查，不能靠进程内计数。每个计划保留独立快照锁和持有者校验。
- 快照持久化保留毫秒级剩余TTL。锁租期仍覆盖配置允许的执行时间、清理余量和安全余量；旧持有者不能覆盖新状态。
- `circuit_breaker.py` 将本地 `RequestTimeout` 与供应商故障分开，正常限时不会累计熔断失败；取消会释放本次半开探测，供应商自身的 `TimeoutError` 仍按故障统计。
- `agent_execution.py` 不因暂停结果缺少索引覆盖数据就触发自动补索引；`agent_tools.py` 对空的暂停结果明确提示可以继续查找。
- `search_tasks.py` 对可续结果标记 `resumable`，对无可续游标的累计额度等终止原因标记 `failed`。所有写入保留generation校验；旧任务取消后不能向新搜索发布结果。

## 边界与兼容性

1. 首次查询若在自动解析完成、计划保存之前超时，仍需重新发起，没有可续游标。本轮没有引入 `parse_pending` 状态。计划建立后的初始化和核验超时可以续查。
2. 后台任务暂停后由用户的前台续查继续处理，未新增自动重投循环。
3. 旧预算记录继续原绝对deadline语义直到自然过期；新代码不把旧记录迁移成满额v2预算。API请求字段和游标格式保持，无数据库迁移。
4. 部署时API与Worker应一起更新预算读写实现。旧代码不支持v2预算；回滚前应停止新搜索、等待现有计划的最大剩余TTL结束，再切换回旧实现。本轮仅修改工作区，未部署业务容器。
5. 本轮验证工程行为，没有重跑真实模型检索评测，不能据此宣称准确率、召回率或实际响应延迟提升。
