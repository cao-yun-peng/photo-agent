# P5：生成取消、恢复、受控迭代与进度

任务 S6-P5-001，2026-09-06。承接 P4 的冻结方案与用户确认，仅扩展流程包执行生命周期；旧模板 Worker 保持原路径。Agent 生命周期仍为阶段 6 revision 4，整体发布 Gate 未推进。

## 用户体验

生成详情显示等待确认、排队、输入校验、模型生成、结果核验、保存等实际步骤，不估算百分比。完成后展示核验问题和模拟结果标记；核验不通过不会自动重画。

未执行的任务可取消，确认凭证立即失效并释放本地额度预留。已进入模型调用的任务先显示“已请求停止”：系统不声称撤销了供应商处理或费用；返回后停止展示结果。任务已完成则不能取消，可保留结果并提交具体调整要求。

“预览调整方案”会沿用冻结原图、风格参考和上轮创作指令，创建有父子关系的新任务。它不是直接在上一张输出上局部修补，也不保证输出连续性。每轮重新查看方案、费用和确认；原结果保留。默认每组最多 2 次调整、累计估算上限 1.00 元（含初始任务，取消/过期调整也计入次数与估算）。限制是任务组预算，不是账户全局预算或供应商硬限额；账户仍使用日额度。并发重复请求只保存一个同键方案，规划模型可能在锁前重复调用。

调整任务不能通过普通方案调整入口绕过父子记录：如需改写，取消后从上一结果重新提交；取消仍占用该组一次调整名额。结果未知的任务不会提供继续迭代按钮，需要先人工核实供应商结果。

- `POST /generations/{id}/iterations`：`{feedback: string(1..500), idempotency_key: string(8..128)}`。仅已完成流程包，返回 awaiting_confirmation；不自动入队。

## 取消与恢复语义

| 情况 | 处理 |
| --- | --- |
| 等待确认 / 排队 / 入队失败 / 输入校验期间取消 | cancelled，失效凭证和租约，释放预留；Worker 不调用模型 |
| 模型调用开始后取消 | cancel_requested，等待返回；不再展示输出，已返回调用计入额度和适配器费用 |
| 模型调用超时、断连 | outcome_unknown，释放本地预留，供应商结果/费用待核实，绝不自动重复调用 |
| Worker 租约过期 | 旧 token 失效，后到结果不能结算/覆盖；调用边界后进入 outcome_unknown，调用前失败 |
| 排队长期无人消费 | queue_failed，保留任务与预留，用户可重试入队或取消，不自动发起新模型任务 |
| 方案确认过期 | expired，凭证失效 |

Worker 在模型调用前持久化调用边界；每次阶段推进和最终结算重新锁行、校验 token 与有效期。不会在网络调用期间持有生成行锁。固定租约默认 300 秒，高于现有 ARQ 180 秒任务超时；恢复在 Worker 启动及每分钟第 10/40 秒扫描，每批最多 100 行，使用 skip_locked。旧 Worker 无 token 不得混跑。

已获得模型返回时先持久化适配器费用，再进行核验/保存。晚到的 OSS 写入使用独立尝试路径，不能覆盖其他结果；若租约随后失效，该未关联对象可能残留，需后续对象清理，不自动认定为已交付。供应商返回未知时无法进行自动费用对账，费用字段不能解释为退款/零成本。
