# P6：稳定选片、明确记忆、相册与撤销

S6-P6-001，2026-09-06。开发切片与隔离验证，生命周期仍为阶段6 revision4，完整发布Gate保持。

## 使用流程

Web侧栏“选片与相册”打开持久选片区。搜索每张结果新增“加入选片区”，搜索区链接可把当前最多100张候选带入工作区；原来的“选择这张”仍用于对话里的单图确认。两者职责不同，加入选片不构成生成授权。

已选集合不会因搜索翻页、换轮或刷新而清空。工作区可以保存目标说明、张数、至少合照数量、风景优先和固定照片；再点击“按已保存目标筛选”。优先保留固定照片、满足已有people_count认定的合照数量、增加场景覆盖，参考明确偏好与分辨率。同分按候选原始顺序，按文件hash去除完全相同项，并对可用缩略图使用dHash、平均颜色和画幅比例判断近似候选组，每组优先保留一张，固定照片例外。缺少足够照片/合照时报告实际数量，不补造结果；说明持久化，照片失效后提示重新核对。

这是基于已有分析的确定性选择，不是审美模型打分。分辨率不等于清晰度，近似重复是启发式候选，可能误判，必须人工核对；缺少缩略图或超时的照片明确报告未检查。每张缩略图限2MiB/400万像素、4路并发、总等待8秒；不下载原图替代，也不删除照片。目标文本供Agent理解，日期等搜索条件仍由上游搜索筛选，工作区不把自由文本当作已执行的过滤器。

可以移除某张、固定某张、清空本次目标、保存新相册、用当前选片更新相册、载入或移除相册。成员保持顺序，删除原照片时成员级联移除。移除相册是可撤销的软删除，绝不删除原图。首版每用户一个共享工作区，最多100张选片、200条相册记录（含软删除）和100张照片事实修正，未实现多工作区并行编辑。

## 三类记忆

| 类型 | 位置与来源 | 冲突规则 |
| --- | --- | --- |
| 本次任务 | 目标、数量、合照下限、固定/排除ID；用户界面明确操作 | 与选片集合一起版本化；清空选片会清空本次目标 |
| 明确偏好 | 人物/风景优先、标题auto/none；显式保存且可清除 | 本次目标优先于常用偏好；拒图、点击不写入长期偏好 |
| 照片事实修正 | 自由文本160字、来源、时间、照片版本摘要 | 照片文件/元数据版本变化后标记过期，不作为有效事实发送给Agent |

任务与偏好分别记录更新时间，事实记录独立时间与版本。事实修正仅作为用户声明的资料，不改原图、AI分析或搜索索引；“杭州不是苏州”不会自动重建向量或更改地理过滤。过期修正可删除或重新核对后提交；已删除照片对应的隐含历史修正可通过“清除全部事实修正”删除。

新增只读Agent工具 `read_workspace`，在用户提及已选照片、本次目标或记忆时按需读取结构化数据；当前明确请求优先，不把记忆文字提升为系统权限。返回来源、工作区revision与当前有效照片修正，不继承reasoning内容。相册/记忆写入与撤销通过用户工作区完成，没有向模型开放通用修改数据库或自动长期记忆工具。标题偏好可由Agent读取用于规划，不会静默覆盖Web明确指定的标题策略。

## 原子操作与撤销

- `GET /workspace`：当前版本、有效选片、任务、偏好、相册摘要、明确修正、当前可撤销操作和筛选说明。
- `POST /workspace/actions`：类型包括add_selection/remove_selection/clear_selection/set_task/set_preferences/set_fact/clear_fact/clear_facts/curate/save_album/load_album/delete_album；每次带expected_revision和idempotency_key。
- `POST /workspace/actions/{operation_id}/undo`：带expected_revision，只允许同用户最新未撤销操作，10分钟有效；重复撤销返回当前状态。
- `GET /workspace/albums/{id}`：私有有序照片列表。

同用户操作通过用户行/工作区行锁串行化；旧版本返回409，不覆盖新状态。同键同请求回放原receipt，不再写入；同键不同请求拒绝。状态、相册成员、撤销快照在一个事务提交，响应快照在释放锁之前构建。

撤销校验用户、revision、时限及被恢复照片的当前可用性。若另一个标签页已更新、照片已删除或不再可访问，则拒绝撤销。只能撤销最新一步，不支持多层undo/redo；撤销会推进revision，避免回到旧版本号。照片参与写入时使用共享行锁，减少校验后删除/变更的竞争窗口。

撤销历史可能短暂保留被清除的偏好/事实，供用户撤销；过期before快照在后续用户操作及Worker每分钟20秒清理，后台每批最多500条，已撤销快照立即清空。保留不含原始内容的操作摘要/幂等hash。Worker停机时，过期清理延至恢复或下一次写入；不宣称数据在10分钟整立即物理删除。
