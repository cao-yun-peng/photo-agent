# 测试账号图片召回开发集 v1

基于 `Photo Eval Dataset v2` 测试账号的 **137 张图片，217 条中文查询**。数据库只读快照、原始清单与本地图片的 SHA-256 已逐一匹配。`corpus.json` 提供 p-ID、实际数据库 UUID 和图片路径映射，可直接对照项目检索结果。

| 主切片 | 查询数 | 目的 |
|---|---:|---|
| visual_semantic | 137 | 每张图片至少一个具体视觉语义查询 |
| colloquial | 20 | 用户口语、省略与间接描述 |
| ocr | 30 | 可见文字、票据、招牌、屏幕内容 |
| multi_positive_or_exclusion | 20 | 多个相关结果、否定条件、相似图辨别 |
| zero_result | 10 | 当前相册不存在满足全部条件的图片 |

覆盖猫狗相似图、杯子与咖啡、婚礼、食物、实拍屏幕与应用截图、路牌和票据，以及模糊、反光、遮挡等困难图片。p-162/p-163 是需要特别关注的近重复猫图。无结果题仅针对这 137 张图片的封闭语料。

## 文件与使用

- `queries.csv`：Excel 可读的中文查询和答案，建议先在这里复核。
- `queries.jsonl`：机器读取格式，包含正例、困难负例、切片和标注状态。
- `corpus.json`：137 张图片的 p-ID / 数据库 UUID / 路径 / 哈希映射。
- `qrels.tsv`：TREC 四列格式的 29,729 个二元暂定判断。正例之外的图片显式写为 0；这些不是逐对人工审定的负例。
- `visual_queries.tsv`、`challenge_queries.json`：可修改的查询源文件。
- `account_snapshot.json`、`dataset.meta.json`：只读账户快照与可重建性哈希。

在项目根目录执行，不调用模型：

```powershell
python scripts/build_retrieval_dataset.py
python scripts/eval_retrieval.py
python -m unittest tests.test_retrieval_dataset -v
```

修改查询源文件后重新生成。评分前会核验源文件、产物及全部原图哈希，并检查标签与 qrels 一致性。

实际评测时，以该测试用户登录，逐条仅发送 `query` 给被测检索链路，保持同一语料快照，固定 top-k、阈值、模型和检索配置。**不得向被测模型传入正负例、答案文本或图片 ID；困难负例不能作为请求的排除项。** 推荐分别记录直接检索和完整 Agent 两种运行，不能混为同一个分数。保存每条最终返回的有序图片列表，包括失败查询（空列表，并在运行日志记录错误）。结果文件格式如下，须包含全部 217 条查询各一次：

```json
{"query_id":"recall-001","photo_ids":["p-004"],"latency_ms":125.0}
```

这里仅演示格式，不是实测输出；`photo_ids` 也接受数据库 UUID。运行：

```powershell
python scripts/eval_retrieval.py --results results.jsonl --output recall-report.json
```

评分提供总体及各主切片的 Recall@1/5/10、Precision@1/5/10、MRR@10、nDCG@10、困难负例命中率、重复数和已提供的延迟均值；每项同时记录样本数。无结果题单独算空结果准确率，不纳入 Recall/MRR/nDCG。重复结果占排名但不重复得分；Precision 分母固定为 k。遗漏查询、重复查询、未知或跨语料图片 ID 会报错，避免静默丢弃。返回少于 k 条结果时仍按实际返回列表评分。报告附数据集和结果哈希。

## 标注依据与修正

本轮通过 6 张联系表查看全部图片，并放大核实 p-153 路牌；证据位于 `.project-to-act/tasks/S6-L3-DATASET-001/evidence/`。查询依据图片视觉内容创作，旧 VL 标签仅作辅助，没有用项目召回结果反推答案。

1. **p-153** 实际文字为“西四南大街”，旧清单的“西四环南大街”多了“环”。新查询采用正确文字，并添加必须含“环”的无结果题；原始清单未覆盖修改。
2. **p-134** 衣服呈现 `I + 爱心图形 + NY`，不能当成图上存在字面单词 `LOVE`。
3. **p-163** 不沿用旧标签“望向窗外”，以图片中朝向和位置辨别；p-162 与它单独保留。
4. **p-158** 使用雾气/水迹玻璃后的街景描述，不强断定是镜头起雾；p-066 按电视描述，不当成电脑。

137 条单图语义题的困难负例由旧对象标签交集挑选，属于**候选困难负例**；其他题的负例随查询编写。所有正负例都标为 `codex_draft_pending_independent_review`，尚未经过独立标注者审定。宽泛集合题尤其需要检查漏标；不要将这个草案分数解释为人工金标准确率。

## 适用边界与下一步

这是 **Development 开发集**，不是盲测集，也没有新鲜的实际召回分数。137 张均来自合成数据，其中 25 张是带 AI 生成标识的拟真困难图，不代表真实个人相册分布。所有图片的拍摄时间与位置元数据均为空，因此未编写依赖真实拍摄日期或 GPS 的题；票据和日历中的文字不等于拍摄元数据。

下一步由独立复核者逐题检查全部候选相关图片与负例，确认无结果题，记录复核人及标签版本；再使用未参与调参的新图片与新查询建立 Validation/Test。不能把同义问法、共享图片和近重复图片随机拆入不同集合。原 VL 的 `source_vl_split` 只保留来源，不能直接继承为这批检索查询的盲测身份。跨用户隔离、真实负载及发布门槛仍由独立测试覆盖，本数据集不使发布 Gate 通过。
